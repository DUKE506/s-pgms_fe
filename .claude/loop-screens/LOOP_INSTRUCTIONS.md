# Loop 절차 — 화면 1개 구현

`TASK.md`의 정지 조건을 항상 우선한다. 아래는 정지 조건에 걸리지 않는
정상 경로.

## 1. 다음 대상 확인

- `PROGRESS.md`를 읽고 현재 상태 확인 (진행 중인 항목이 있으면 그것부터)
- 없으면 `docs/roadmap.md`에서 다음 미체크 화면 항목을 하나 고른다
  (Phase 순서대로, 같은 Phase 안에서는 위에서부터)
- 항목에 묶인 목업 anchor id(예: `s4`, `s4m`)를 `docs/PGMS_UI_mock.dc.html`
  에서 찾아 해당 섹션(데스크톱 + 모바일 있으면 둘 다)을 읽는다

## 2. 사전 점검 (정지 조건 해당 여부)

- 화면에 필요한 UI 패턴(모달, 드롭다운, 탭, 아바타 등)이
  `src/components/ui/`에 이미 있는지 확인. 없으면 **여기서 멈추고 사용자에게
  물어본다** — 새 shadcn 컴포넌트를 추가할지, 다른 방식으로 대체할지
- 화면이 다루는 데이터/필드가 `docs/project-overview.md`,
  `docs/architecture.md`(API 계약)에 이미 정의돼 있는지 확인. 안 되어
  있으면 임의로 채우지 않고 물어본다

## 3. 구현

- `src/app/routes.tsx`에서 해당 라우트의 `ScreenPlaceholder`를 실제
  컴포넌트로 교체
- 필요하면 MSW 핸들러/fixture 추가 (`src/mocks/handlers/`, `src/mocks/data/`)
  — 이미 구조가 있으니 그 패턴을 따름
- 기존 shared 컴포넌트(`Button`/`Card`/`Table`/`Dialog`/`StatusBadge`/
  `Sidebar` 등)와 디자인 토큰을 재사용, 새로 발명하지 않음
- 필요한 로직(상태 전이, 관리번호 체계 등)은 유닛/통합 테스트로 커버

## 4. 검증

1. `npm run test`, `npm run lint`, `npm run build` 모두 통과 확인
2. `run-s-pgms` 드라이버로 실제 로그인 → 해당 화면까지 이동 → 스크린샷
   (데스크톱, 모바일 목업이 있으면 `viewport 390 844`로 모바일도)
3. `console` 커맨드로 콘솔 에러 없는지 확인

## 5. 제시 + 승인 대기 (★ 여기서 반드시 멈춤)

- 스크린샷과 함께 무엇을 구현했는지 간단히 요약해서 사용자에게 보여준다
- **사용자의 명시적 승인 전까지는 다음 단계로 진행하지 않는다**
- 수정 요청이 오면: 반영 → 4번(검증)부터 다시 → 다시 제시

## 6. 승인 후 마무리

- `docs/roadmap.md`의 해당 체크박스에 `[x]`
- `PROGRESS.md` 갱신 (완료로 표시, 커밋 해시 기록)
- 커밋 (구현 커밋 + roadmap 체크 커밋, 지금까지 해온 방식대로 분리하거나
  사용자가 원하면 합침 — 커밋 전 항상 사용자에게 확인)
- 다음 iteration으로 — 단, 자동으로 이어서 진행하지 않고 사용자가
  "다음 화면"이라고 말하면 1번부터 다시 시작
