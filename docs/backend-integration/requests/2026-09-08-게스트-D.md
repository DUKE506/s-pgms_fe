## 1. 게스트 계정 "중지"(`useYn`) — 화면 설계에 없음 (논의, issues #1 게스트 facet)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `GetGuestUserList`가 중지된 계정도 `useYn=false`로 함께 반환. 스키마·DB엔 `useYn` 축이 있음 |
| 프론트 처리 | 우리 화면엔 "게스트 계정 중지/재개" 기능이 없다(발급·조회권 수정·삭제만). `useYn=false` 행을 목록에서 숨기고 있음 |
| 논의 필요 | 게스트 계정 중지가 실제 업무 요건인지 확인. **요건이면** 화면에 중지/재개 액션 + 상태 컬럼 추가(기획), **아니면** `GetGuestUserList`가 `useYn=true`만 반환하거나 프론트 숨김 유지로 종결. 현재는 프론트 숨김으로 진행 중 |

## 2. 게스트 상세(`GetDeployDetail`) 조회권 스코프 서버 보장 (논의)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `GetDeployList`는 게스트 토큰에서 `?groupSeq=`를 무시하고 `GUEST_CASE_ACCESS` 스코프만 적용함을 실측(조회권 건만 반환). `GetDeployDetail?deployReqSeq=`는 **조회권 있는 건 200**만 확인 |
| 미검증 | 게스트가 **조회권 없는 건**의 `deployReqSeq`로 상세를 직접 호출하면 403/404로 막히는지 — 테스트 시점에 동래에 게스트 미부여 *진행중* 건이 없어(활성 1건뿐, 게스트가 봄) 양성 테스트 불가 |
| 논의/확인 | `GetDeployDetail`(및 게스트가 도달 가능한 다른 조회 EP)도 `GUEST_CASE_ACCESS` 스코프를 서버에서 강제하는지 확인. 안 걸리면 프론트에서 조회권 화이트리스트로 상세 접근을 막아야 함(현재는 목록에 조회권 건만 떠서 링크 자체가 없음 — 방어선만 필요) |
