# 백엔드 요청·논의 — 섹션 C (이력 조회)

> **작성일**: 2026-09-08 · **대상 섹션**: 그룹 C (이력) — [본사] #13 · [경찰서] #14 · [본청]/[지역청] #15
> **상태**: 백엔드/운영본부 전달 예정. 근거는 `docs/backend-integration/findings.md` #14·#15.

**연동 완료분(요청에서 제외)**: [본사] 목록(`History/Stec/W/GetHistoryList`),
[경찰서] 목록+상세(`History/Police/W/GetHistoryList`·`GetHistoryDetail`).

유형: **요청**(백엔드 구현) / **논의**(스코프·설계 확인)

## 1. [본사] 이력 상세 조회 EP가 없음 — 요청 (issues #14)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `History/Stec/W/GetHistoryDetail` → **404**(경로 없음). `History/Police/W/GetHistoryDetail` → 본사 토큰에 **403**. 목록은 `History/Stec/W`·`History/Police/W` 둘 다 있는데 상세는 Police만 있는 비대칭 |
| 필요한 것 | `History/Stec/W/GetHistoryDetail` 신설(Police 응답과 동일 shape, 본사 스코프: 운영/시스템=전국, 본부관리자=본인 배정 건 HIST-003) **또는** `History/Police/W/GetHistoryDetail`을 본사 토큰도 호출 가능하게 권한 확장 |
| 임시 처리 | `/admin/history/:id` "이력 상세 조회는 준비 중입니다" 안내. 목록은 정상 연동 |

## 2. [본청]/[지역청] 이력 — 관할 전체를 한 번에 못 받음 — 요청 (issues #15)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `GetHistoryList`가 `groupSeq` **경찰서(leaf) 노드일 때만** 데이터를 줌. 부모 노드(본청 22·지방청 24) → 0건. 지방청·본청이 관할 전체를 한 번에 못 받음. `Deploy/Police/W/GetDeployList`(진행중 목록)도 동일하게 leaf 단위 |
| 필요한 것 | `GetHistoryList`(+진행중 목록 EP)가 **부모 `groupSeq`를 받으면 그 노드 이하 전체를 캐스케이드**로 반환. 스코프는 `Login/W/GetGroupTree`가 이미 나누는 서브트리 규칙 재사용(본청=전국, 지방청=관할 이하) |

## 3. [본청]/[지역청] 이력 — 진행중 건이 목록에 안 나옴 — 요청 (issues #15)

| 항목 | 내용 |
|---|---|
| 지금 상태 | 이 역할은 대시보드(Phase 4)가 없어 이력 화면이 전체 현황을 겸함(2026-08-27 결정). 그런데 `GetHistoryList`는 종결·취소만 주고 `status`/`includeActive`/`all`/`isEnd`를 다 무시. 진행중은 `GetDeployList`를 경찰서마다 따로 불러 합쳐야 함 |
| 필요한 것 | (1) `GetHistoryList`에 `status` 파라미터를 실제 동작시켜 진행중 포함 토글, **또는** (2) 본청/지역청용 **통합 조회 EP 신설**(진행중+종결/취소 한 응답, 역할 스코프, 페이지네이션·정렬). **프론트는 (2) 선호** — `GetDeployList` 병합·재정렬 부담이 사라짐 |

## 4. 이력 상세 스코프 확인 — 논의 (issues #15)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `GetHistoryDetail?caseSeq=`·`Deploy/Police/W/GetDeployDetail?deployReqSeq=`가 본청/지역청 토큰에 200 — **타 관할 건 차단 로직 없음**(#14에서도 3역할 다 200) |
| 회신 필요 | 관할 밖 `caseSeq`/`deployReqSeq` 차단을 적용할지. 안 막을 거면 프론트는 목록에서 걸러진 id만 넘기는 현행 유지 |

## 5. 이력 상세 `guardWorkLoc`/`guardHomeLoc` — 논의 (issues #14·#15)

| 항목 | 내용 |
|---|---|
| 지금 상태 | `History/Police/W/GetHistoryDetail` 응답에 배치장소 2필드가 들어옴. #14 연동 땐 "없음"으로 보고 exclusions 처리했는데 2026-09-08 재실측 시 존재. 종결 건 배치장소를 피해자 개인정보로 보고 화면에서 뺐던 설계(roadmap Phase 3)와 충돌 가능 |
| 회신 필요 | 이력 상세에 배치장소를 **의도적으로 주는 건지**. 주는 게 맞으면 프론트가 표시 복원, 실수면 응답에서 제거 |

## 재확인 — 요청에서 제외 (데이터 없어 재검증 예정, 백엔드 요청 아님)

  (경찰 상세 조치)과 같은 성격으로 추가 요청
