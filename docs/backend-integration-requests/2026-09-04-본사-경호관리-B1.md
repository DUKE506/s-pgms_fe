## 요청 1 — 경호계획 등록에 필요한 배치기간 (issues #10)

**API**: `GetGuardCaseDetail` / `GetGuardCaseList` / `AddGuardCaseInfoDto`

**문제**
- `AddGuardCaseInfo`는 `startDt`/`endDt`(배치기간+배치시간)를 **required**로 받는다.
- 배정·경호계획 미등록 상태에서 `GetGuardCaseDetail.startDate`/`endDate`는 `null`
  (경호계획을 등록해야 채워짐 — 닭-달걀). `GetGuardCaseList`도 배정 건은 기간 null,
  `GetDeployRequestList`는 배정되면 목록에서 빠짐.
- 본사·시스템관리자 토큰으로 `Deploy/Police/W/GetDeployDetail`·`GetDeployDetailUpdate`
  호출 시 **403**(2026-09-04 실측) → 배치요구서의 기간을 볼 경로가 전무.

**해결 요청안** (하나면 충분)
1. `GetGuardCaseDetail`(또는 `GetGuardCaseList`)이 경호계획 미등록 상태에서도 배치요구서
   기간(`periodFrom`/`periodTo`)을 반환.
2. `AddGuardCaseInfo`가 `startDt`/`endDt`를 optional로 받고, 미지정 시 서버가 배치요구서
   기간 + 폼이 보낸 배치시간으로 조합.
3. 요청 2(본사용 배치요구서 원본 조회 API)로 함께 해소.

**프론트 임시 처리**: 배정 건에서 경호계획 "등록" 버튼 비활성 + 안내문. "수정"
(`PatchCaseInfo`, 기간 불필요)은 정상 동작.

## 요청 5 — 조치 `summary1~5` 구조화 (issues #11)

경호계획의 조치 섹션 5개는 각각 **여러 항목 선택 + 적용기간(시작/종료)**인데,
`summaryN`·`summaryNDate`가 단일 문자열 2개뿐. 프론트가 `", "`(항목)·`" ~ "`(기간)
규칙으로 직렬화 중 — 백엔드 계약이 아니라 프론트 규칙이라, 다른 클라이언트가 넣은 값과
호환 안 됨. 항목 배열 + `summaryNFrom`/`summaryNTo` 2필드(또는 자식 테이블)로 구조화 요청.

## 요청 8 — 사전미팅 근무자별 시간 (issues #11 사전미팅, 경미)

`PreMeetingDialog`는 근무자별로 시작/종료를 따로 받는데 `SaveCaseMeetingDto`는 미팅 전체
1구간(`meetingStart`/`meetingEnd`) + `guardSeqs[]`뿐. 저장 시 가장 이른 시작 ~ 가장 늦은

단일 구간으로 단순화(그쪽이면 회신 바람).

## 요청 9 — 담당자 소속 본부 (issues #1 부분 — B-2와 공유)

`GetGuardCaseList`가 담당자 이름(`userName`)만 주고 소속 본부는 안 준다. `USER_INFO`에
본부(`BASIC_CODE` 8~14) FK가 없어 자유텍스트 `NAME`을 파싱해야 하는 상태. 본사 경호목록의
"본부" 열·지역청 필터가 무력. `USER_INFO`에 본부 FK 신설 + `GetGuardCaseList`/
`GetStecUserList` 응답에 포함. (관리자 계정 관리 화면 = B-2에서도 같은 데이터 필요 —
issues #1 전체는 B-2 종료 시 재확인.)
