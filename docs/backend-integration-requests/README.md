# 백엔드 일괄 요청서 저장소

`docs/backend-integration-process.md` 원칙 4(개발은 화면 단위, 백엔드 요청은 섹션 단위)에
따라, 한 섹션의 연동 작업 중 `docs/backend-integration-issues.md`에 쌓인 설계 변경/누락
API 요청을 **섹션이 끝날 때 한 번에 묶어** 백엔드에 전달할 문서를 여기 저장합니다.

## 파일 규칙

- 파일 1개 = 섹션 1개. 이름: `{YYYY-MM-DD}-{섹션명}.md`
  예: `2026-09-03-피전-경호관리.md`
- 구조는 **제목 / 요청 목록(API·요청·왜 필요한가) / 각 요청별 설명(API·문제·해결 요청안)**.
- `issues.md`의 항목 번호를 대조용으로 병기하되, 이 문서 자체는 백엔드에 그대로 전달할 수
  있는 형태로 (프론트 내부 맥락 최소화) 작성합니다.

## 갱신 시점

`.claude/loop-backend/LOOP_INSTRUCTIONS.md` 7단계(섹션 종료 시 일괄 요청)에서 작성합니다.
전달 후 응답은 기다리지 않고 다음 섹션으로 진행하며, 완료 통보가 오면 1단계(완료분 반영
확인)에서 코드에 반영합니다. 백엔드 응답 방식이 확정되면 `issues.md`의 해당 항목 상태를
🟡→🟢으로 갱신합니다.
