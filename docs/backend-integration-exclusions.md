# 백엔드 연동 — 제외 항목 로그

`docs/backend-integration-process.md` 원칙 1 적용 항목을 기록합니다. 실제 연동 작업을
화면/기능 단위로 진행하면서 "일단 이 필드/기능은 빼고 연결한다"고 판단한 것들을 발견하는
즉시 아래 형식으로 추가합니다.

## 형식

```
### [화면/기능명] — [제외한 필드 또는 동작]

- **왜 제외했는지**: 백엔드에 없음 / 의미가 다름 / 등
- **사용자가 잃는 것**: 화면에서 뭐가 안 보이거나 동작 안 하는지
- **연동 커밋**: (해당 커밋 해시)
```

---

### 로그인 — `GetMyProfile`의 `groupSeq`/`groupName`(경찰 계정 조직 정보) → **해소됨(matrix 2번)**

- **왜 제외했었는지**: 로그인 연동 시점엔 세션(`AuthUser`)에 `id`/`name`/`role`만
  있고 당장 이 값을 쓰는 화면이 없어 응답에서 버렸음.
- **해소**: matrix 2번(경찰서 경호목록) 연동에서 `GetDeployList`가 `groupSeq`를
  필수 파라미터로 요구해 `AuthUser`에 `groupSeq?`/`groupName?`(optional)를 추가하고
  `login()`이 `GetMyProfile` 응답에서 채우도록 함. 이후 조직 스코프가 필요한 화면
  (matrix 17·18번 등)이 이 값을 그대로 재사용.
- **연동 커밋**: (matrix 2번 연동 커밋)

### 로그인 — 아직 미연동인 화면(경호목록 등)에서 실제 백엔드 세션으로 401 발생

- **왜 제외했는지**: 버그가 아니라 마이그레이션 전환기의 예상된 상태 — 아직 mock인
  화면들(`mocks/handlers/securityCases.ts` 등)은 Authorization 토큰에서
  `access.<mock계정id>.<nonce>` 형식을 파싱해 그 mock계정id로 로컬 seed 데이터(예:
  `gangnam`)를 찾는 방식인데, 실제 백엔드 로그인 성공 시 발급되는 진짜 JWT는 형식도
  다르고(`loginId` 클레임이 `SPoliceM5`처럼 실제 백엔드 계정)애초에 그 계정이 mock
  seed(`mocks/data/accounts.ts`)에 존재하지 않음 — 두 시스템의 계정 자체가 다른
  namespace라 토큰 파싱을 고쳐도 해결되지 않는 구조적 간극. 다음 iteration(matrix
  2~7번, 경찰서 피전 화면군)이 그 화면들을 순서대로 실제 백엔드로 연결하면서 자연
  해소됨.
- **사용자가 잃는 것**: 실제 백엔드 계정으로 로그인 후 아직 미연동 화면에 들어가면
  콘솔에 401이 찍히고(화면 자체는 빈 목록/에러 상태로 렌더링됨) 정상 데이터가 안
  보임 — 로그인 자체와 이미 연동된 화면(현재는 로그인뿐)은 영향 없음.
- **연동 커밋**: (로그인 연동 커밋에 포함 예정)

### 경찰서 경호목록(matrix 2번) — `jurisdiction`(관할 지방청) 표기

- **왜 제외했는지**: `GetDeployList` 응답 항목에 관할/지방청 정보가 없음. mock은
  `jurisdictionForStation`으로 경찰서→지방청을 매핑해 화면 상단을 "관할 / 계정명"
  으로 보여줬음.
- **사용자가 잃는 것**: 상단 breadcrumb이 "부산지방경찰청 / 동래경찰서"류에서
  "동래경찰서"만으로 축소(실측상 `GetMyProfile.groupName`이 계정명과 동일 "동래경찰서"
  라 사실상 같은 정보). 목록 데이터 자체엔 영향 없음.
- **연동 커밋**: (matrix 2번 연동 커밋)

### 경찰서 경호목록(matrix 2번) — 목록→상세 이동이 전환기 동안 미동작

- **왜 제외했는지**: 목록 행 클릭 시 `/security-cases/:id`로 이동하는데, 그 상세
  화면(matrix 4번)이 아직 mock(`findSecurityCase`)이라 실제 `deploySeq` 기반 id로는
  건을 못 찾음.
- **사용자가 잃는 것**: 실제 백엔드 로그인 상태에서 목록 행을 클릭하면 상세가 비어
  보임 — matrix 4번(경호 상세) 연동 시 자연 해소.
- **연동 커밋**: (matrix 2번 연동 커밋)

### 경찰서 경호목록(matrix 2번) — 배정 이후 `statusName` 문자열 미검증

- **왜 제외했는지**: 실측 시점에 동래경찰서 데이터가 "접수" 1건뿐이라, 배정/경호중/
  경호완료/종결/취소 상태의 `statusName` 문자열이 프론트 `SecurityCaseStatus` 라벨과
  정확히 일치하는지 확인 불가.
- **사용자가 잃는 것**: 만약 문자열이 다르면 해당 건이 화면의 `VISIBLE_STATUSES`
  필터에서 빠져 목록에 안 보일 수 있음 — matrix "16번 이후 재확인" 시점에 배정된
  데이터로 검증 예정.
- **연동 커밋**: (matrix 2번 연동 커밋)
