# 민간경호관리 시스템 — 개발 핸드오프

## 프로젝트 개요

경찰(본청/지역경찰청/경찰서)과 민간 경비업체(본사)가 함께 사용하는 민간경호(신변보호) 배치·관리 시스템. 접수부터 배정, 경호 수행, 종결까지 전체 라이프사이클을 다룬다.

## 대상 사용자 / 페르소나

- **경찰 모드**: 본청, 지역경찰청, 경찰서 — 조직 계층에 따라 조회 범위(전국/지역/개별서)만 다르고 화면 템플릿은 동일
- **본사 모드**: 경비업체(에스텍 본사) — 배치요청 접수, 담당자·근무자 배정, 근무 스케줄 관리

경찰 사용자와 본사 사용자는 계정이 분리되어 있으며, 서로 다른 모드에는 접근할 수 없다.

## 모드별 계정 권한

| 모드              | 계정              | 조회/처리 범위                                                       |
| ----------------- | ----------------- | -------------------------------------------------------------------- |
| 경찰 — 본청       | 본청 계정         | 전국 전체 조직/사건 조회                                             |
| 경찰 — 지역경찰청 | 지역청 계정       | 소속 지역 내 사건만 조회                                             |
| 경찰 — 경찰서     | 경찰서(피전) 계정 | 자기 관할 사건 접수/배치요구서 작성 및 처리                          |
| 본사              | 시스템관리자      | 개발팀 계정. 경찰 모드를 제외한 본사 모드 전 기능 사용 가능          |
| 본사              | 운영관리자        | 업무계정 최상위 권한. 시스템관리자와 동일한 범위 (본사 모드 전 기능) |
| 본사              | 본부관리자        | 본인이 배정받은 경호건에 한해서만 조회/처리 가능                     |

경찰 계정 간에는 조직 계층에 따라 조회 범위만 다르고 화면 템플릿은 동일하다. 본사 계정은 경찰 계정과 별도 체계이며 서로 접근할 수 없다.

## 업무 워크플로우

1. **접수**: 경찰서가 배치요구서를 작성해 접수하면 경호건 상태는 **접수**로 생성된다
2. **배치요청 수신**: 본사가 배치요청을 목록에서 확인
3. **담당자 배정**: 본사(운영관리자/시스템관리자)가 담당자를 배정하면 경호코드가 발급되고 상태는 **배정**으로 변경된다
4. **기본정보·근무 스케줄 등록**: 담당 본부관리자가 기본정보 등록 및 근무자 스케줄을 입력해 배정을 완료한다
5. **경호 수행**: 경호 기간이 시작되면 상태는 **경호중**으로 변경되며, 경찰서/본사 양측에서 진행 상황을 조회할 수 있다
6. **경호완료 → 종결**: 경호 기간이 끝나면 상태는 **경호완료**로 변경되고, 경찰서(피전)의 행정 처리를 거쳐 **종결**로 전환된다
7. **이력 조회**: 종결/취소 건은 각 조직 단계(본청/지역청/경찰서/본사)의 이력 조회 화면에서 조직트리 필터로 조회한다

취소는 접수 단계에서는 경호건이 DB에서 삭제되며, 배정 단계 이후(경호코드 발급 후)에는 상태가 **취소**로 변경되고 이력에는 관리번호로 기록된다.

### 전이 규칙

접수 → 배정 → 경호중 → 경호완료 → 종결 이 정상 흐름이다.

- **접수 상태에서 취소**: 경호건 자체가 DB에서 삭제된다 (상태값으로 남지 않음)
- **배정 상태 이후 취소**(경호코드 발급 후): **취소** 상태로 전환되어 이력에 남는다

## 관리번호 체계

- 접수번호 형식: `YY-MM-경찰서명` (예: 26-01-강남서)
- 경호코드 형식: `ST` + 순번 3자리 (예: ST001) — 개별 경찰서 단위가 아니라 **전 경찰서 통합, 연 단위로 발급되는 일련번호**다. 즉 강남서 001건 다음 접수 건이 부산경찰서 소속이어도 002를 이어받는다.
- 관리번호 = 접수번호 + 경호코드

### 취소 건의 관리번호 예외

취소 상태의 건은 다른 상태처럼 "ST접수번호"만으로 식별하지 않고, **관리번호(접수번호 + 경호코드)** 로 표기한다. 이력 조회 화면(1h/2h/8/8h/12) 전반에 이 규칙이 적용된다.

## 참고사항 (개발 시)

- 화면 사양은 별도 디자인 목업(Claude Design)을 기준으로 작성되었으므로, 픽셀 단위 값은 실제 구현 시 그리드/반응형 규칙에 맞게 재해석 필요
- 본청/지역경찰청 대시보드는 컴포넌트를 공유하고 데이터 스코프 파라미터만 다르게 설계할 것을 권장
- 웹앱은 반응형 개발이 필요하며, 반응형 구현 결과를 보고 PWA 적용 여부를 검토할 수 있음
